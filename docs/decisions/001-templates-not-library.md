# ADR-001：交付「可粘贴模板」而非「常量库」

**日期**：2026-09-01
**状态**：已采纳

## 背景

立项时的设想是：把历史 workflow 脚本里的高频代码段抽成常量库，之后写脚本只需引用名字，从而减少 token 消耗。

## 决定

**不做常量库，交付可粘贴模板目录。**

## 理由

### 1. 机制上不可能

Workflow 脚本沙箱在 AST 层面**禁止 `import` 与 `require`**：

```
import() is not available in workflow scripts.
```

没有模块系统，就没有"引用"这个动作。任何"库"最终都要以文本形式出现在脚本里。

### 2. 历史上从未真正复用过

语料实测（46 个唯一脚本体）：

| Schema 名 | 声明次数 | 唯一签名数 |
|---|---|---|
| `PLAN_SCHEMA` | 11 | **11** |
| `VERIFY_SCHEMA` | 9 | **9** |
| `REVIEW_SCHEMA` | 8 | **8** |
| `VERDICT_SCHEMA` | 3 | 1 |

`PLAN_SCHEMA` 声明 11 次产生 11 个互不相同的结构。**被复用的是命名习惯，不是代码。**

唯一真正复用的 `VERDICT_SCHEMA`（3 次声明 1 个签名）之所以能复用，是因为它不含任何任务特定字段 —— 小、抽象、只表达决策而非内容。

这说明：schema 天然是任务特定的。强行统一会削足适履。

### 3. 收益本来就不存在

写脚本占一次 run 的 **0.8%**。为 0.8% 做抽象，收益低于维护成本。

## 后果

- `templates/` 下的文件是**成品脚本**，复制后改 CONFIG 段即可跑
- `references/schemas.md` 明确写"这是起点不是标准，按任务改字段是正常的"
- SKILL.md 只常驻真正跨任务稳定的东西（meta 四段式、`S_STR_ARR`、约束句式）

## 替代方案（未采纳）

- **把常量塞进 SKILL.md 让它常驻**：SKILL.md 每次触发都进上下文，塞 63KB 等于每次烧 3.7 倍于内置参考的量。已设 ≤5200 字符门禁。
  （门禁值修订：2026-09-02 上调至 ≤7000。5200 是插件骨架期初值；OpenSpec-first 常驻规则与显式 peer-handoff 例外段属于跨任务稳定知识，保留常驻，上调后当前占用 6659。）
- **写一个预处理器把 `@include` 展开成脚本**：增加一层构建，且 Workflow 工具接受的是脚本文本，展开后仍要整段传入 —— 没省下任何 token，只增加了失败面。
